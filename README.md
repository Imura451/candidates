# 候補者紹介LP ジェネレータ

インタビュー動画のリンクを送るだけでは伝わりにくいので、**顔写真・簡単な候補者情報・インタビュー動画**の3点をまとめた紹介ページを、候補者1人につき1ファイルのHTMLで書き出す仕組みです。
詳しい経歴・資格は履歴書で別途お渡しする前提なので、ページには載せません。

公開は GitHub Pages。**候補者のJSONと顔写真を置いて `2-公開.bat` を実行すると、企業に渡すリンクが自動で発行されます。**

- Node.js の標準機能だけで動きます。`npm install` は不要です
- 出力は1ファイル完結。CSSも顔写真もHTMLの中に入ります（動画はYouTubeから再生します）
- 検索エンジンには載りません（全ページ `noindex` ＋ `docs/robots.txt`）
- URLは8桁の文字列付きなので、推測して開かれることはありません
- 連絡先は載せません。会社名とロゴだけです
- A4縦1枚で印刷できます。印刷時は動画の代わりにURLが出ます

## フォルダの中身

```
05_candidates/
├── 1-初回設定.bat          # 最初の1回だけ。GitHub につなぐ
├── 2-公開.bat              # 毎回これ。ビルドして公開する
├── data/
│   ├── _sample.json        # 記入例（説明つき）。これをコピーして書き始める
│   ├── _schema.md          # 各項目の説明書
│   ├── _salt.txt           # URLを決める秘密の文字列。絶対に消さない・変えない
│   ├── _slugs.json         # id とURLの対応表（記録用）。消さない
│   └── <id>.json           # 候補者1人ぶんのデータ（_ で始まらないものがビルド対象）
├── assets/
│   ├── logo.png            # 会社ロゴ。各ページに埋め込まれる
│   └── photos/<slug>/      # 候補者ごとの顔写真 face.jpg を置く（初回ビルドで自動作成）
├── src/
│   ├── template.html       # 候補者ページの雛形（{{項目名}} を差し替える方式）
│   ├── style.css           # 候補者ページのデザイン。ビルド時にHTMLへ埋め込まれる
│   └── index.html          # 社内用一覧の雛形
├── build.js                # data/*.json → docs/c/<slug>.html を生成
├── .github/workflows/      # GitHub 側で自動ビルド・自動公開する設定
├── tools/make-bats.py      # .bat を作り直すスクリプト
├── docs/                   # ビルド結果（自動生成。GitHub には送りません）
└── README.md               # この手順書
```

会社名や代表者名は `build.js` 先頭の `COMPANY` にあります。ここを直せば全ページに反映されます。

## 先に読んでください ― Public で公開しています

無料プランでページを公開するため、保存先は **Public（公開）** にしています。
これは「ページを見られる」だけではありません。**このフォルダの中身が、そのまま誰でも見られる状態になります。**

| 見られるもの | 場所 |
|---|---|
| 候補者ページ | `https://imura451.github.io/candidates/c/…` |
| 候補者のJSON（`data/`） | github.com の保存先 |
| 顔写真の元ファイル（`assets/photos/`） | 同上 |
| 過去の変更の履歴 | 同上 |

候補者ページ側の「検索エンジンに載せない」設定は、github.com のほうには効きません。
URLを知らない人でも、保存先から候補者の一覧を辿れます。

### だから、こうしてください

- **本人の同意を取ってから追加する。** 顔写真と基本情報をインターネットに載せることを、候補者本人に説明して同意を得てください
- **フルネーム、生年月日、在留カード番号、パスポート番号は書かない**（これまでどおり）
- **一度送ったものは、あとから消しても履歴に残ります。** 追加する前に中身を確認してください
- 掲載をやめるときは `data/` からJSONを外して再公開します。ページは消えますが、履歴には残ります

これが困る場合は、月4ドル程度の GitHub Pro にすれば非公開のまま公開できます。
無料のまま非公開にしたい場合は、Cloudflare を使う方法もあります（コーポレートサイトと同じ仕組み）。

## 最初の1回だけ ― GitHub に公開できるようにする

### 手順1. GitHub のアカウントと保存先を作る

1. https://github.com でアカウントを作る
   - アカウント名（Username）は **`Imura451`** です
   - 公開URLでは小文字になります（`imura451.github.io`）。GitHub の仕様なので、そのままで問題ありません
2. 右上の「＋」→ New repository
   - Repository name: `candidates`（この名前もURLに出ます。変えないことをお勧めします）
   - **Public** を選ぶ（無料プランで公開するにはこちらです。次の章を読んでから進めてください）
   - README などのチェックは**付けない**（空のまま作る）
   - Create repository

### 手順2. `1-初回設定.bat` をダブルクリック

保存先のURL（`https://github.com/Imura451/candidates`）を聞かれるので、貼り付けて Enter。
ブラウザが開いたら GitHub にログインして許可してください。**ログインは最初の1回だけです。**

### 手順3. GitHub の画面で Pages をオンにする

1. ブラウザで保存先を開く
2. 上のほうの **Settings** → 左メニューの **Pages**
3. Build and deployment の Source を **GitHub Actions** にする

2〜3分後に公開されます。以降、この操作は不要です。

## 候補者を追加する（毎回の手順）

### 1. 動画を YouTube に「限定公開」でアップロードする

公開設定は必ず **限定公開**。「公開」にすると誰でも検索できてしまいます。URLをコピーしておきます。

### 2. 記入例をコピーして JSON を書く

`data\_sample.json` を `data\vn-02.json` のような名前でコピーして、中身を書き換えます。
項目の意味は `data\_schema.md` にあります。

- **`id` は必ず他の候補者と違う値にしてください**
- 記入例の値にある（ ）書きは説明なので消してください
- `video.youtube` に手順1のURLを貼ります

### 3. `2-公開.bat` をダブルクリック

ビルドして GitHub に送ります。画面に**企業に渡すURL**が出ます。
このとき、顔写真を置くフォルダ `assets\photos\vn-xxxxxxxx\` も自動で作られます。

### 4. 顔写真を置いて、もう一度 `2-公開.bat`

手順3で出来たフォルダに `face.jpg` を入れて、もう一度実行します。
「確認してください」に何も出なくなれば完成です。

### 5. URLを企業に送る

画面に出たURL、または社内用一覧のコピーボタンからどうぞ。

| ページ | URL |
|---|---|
| 企業に渡す候補者ページ | `https://imura451.github.io/candidates/c/vn-xxxxxxxx.html` |
| 社内用一覧（企業には渡さない） | `https://imura451.github.io/candidates/` |

公開されるまで2〜3分かかります。うまくいったかは、保存先の **Actions** タブで緑のチェックが付いたかで分かります。

## 覚えておくこと

### URLは一度決まったら変わりません

URLの8桁は、`data/_salt.txt`（秘密の文字列）と `id` から計算しています。同じ `id` なら、何度ビルドしても、どのパソコンでビルドしても同じURLです。
**企業に渡したあとでも中身を直せます。**

**`data/_salt.txt` は絶対に消さない・変えないでください。** 変えると全員のURLが作り直しになり、渡したリンクが切れます。
`data/_slugs.json` も記録として残しておいてください。

### `"draft": true` は社外に出す前に消す

`true` のあいだはページの上に赤い帯で「サンプル／下書きです」と出ます。
一覧でも「下書き」と表示されます。完成したら `false` にするか、行ごと消してください。

### 候補者を非公開にする

`data/` からその候補者のJSONを外して `2-公開.bat` を実行すると、ページも消えます。

### 手元だけで確認したいとき

```bash
node build.js
```

`docs\index.html` をブラウザで開けば、公開せずに見た目を確認できます。

### デザインを直したいとき

- 見た目は `src/style.css`、ページの構成は `src/template.html` です
- `2-公開.bat` を実行すると、全候補者のページに反映されます

### `.bat` を直したいとき

`tools/make-bats.py` を直して `python tools\make-bats.py` を実行します。
バッチファイルを直接編集しないでください。日本語Windowsのcmdが誤解する文字が混ざると動かなくなるため、このスクリプトで検査してから書き出しています。

### 載せてはいけないもの

- フルネーム、番地までの住所、生年月日、パスポート番号、在留カード番号、家族の実名
- 費用や料金。1案件ごとに提案書と見積りで出します
- 「真面目です」「頑張ります」のような、誰にでも当てはまる言葉

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| `2-公開.bat` がエラーで止まる | 画面のメッセージ。JSONのカンマ抜け、`id` の重なりが多いです |
| URLを開くと 404 | Pages の設定（Source が GitHub Actions か）。公開直後は2〜3分待つ |
| 内容が古いまま | 保存先の Actions タブで、緑のチェックが付いているか |
| 顔写真が出ない | `assets\photos\<URLの文字列>\face.jpg` に置いたか。ファイル名は `face.jpg` |
| 動画が出ない | `video.youtube` のURL。限定公開でも埋め込みは動きます |

## サンプルデータについて（重要）

`data/sample-vn-01.json` と `data/sample-np-01.json` は **形を見てもらうための架空の候補者**です。
実在の人物ではありません。`"draft": true` にしてあるので、そのままでは社外に出せません。

- **動画のURL** は `https://youtu.be/REPLACE-ME` です。実在しないので再生できません
- **在留資格・試験の名称** … 制度は変わります。最新の要件は出入国在留管理庁で要確認です

公開を始める前に、この2件は `data/` から外すことをお勧めします。
